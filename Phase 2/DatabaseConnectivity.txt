Tera MERN background hai, toh main har concept ko Mongoose se compare karke
samjhaunga. .NET ka "Mongoose" hai -> Entity Framework Core (EF Core)

Fark sirf itna hai: Mongoose schema-less MongoDB ke liye hai (NoSQL),
EF Core relational DB (SQL Server / PostgreSQL / MySQL / SQLite) ke liye hai.
Isliye yahan "Tables + Relations" ka concept aayega, jaisa SQL me hota hai.

STEP 0: TERMINOLOGY MAPPING (MERN -> .NET)

Mongoose.connect(uri)          -->  DbContext + Connection String
mongoose.Schema                -->  C# Model class (POCO)
mongoose.model("Book", schema) -->  DbSet<Book> Books  (inside DbContext)
MongoDB (NoSQL, flexible)      -->  SQL Server/PostgreSQL (relational, fixed schema)
.env file (MONGO_URI)          -->  appsettings.json ("ConnectionStrings")
No migration needed in Mongo   -->  "Migrations" needed (schema ko DB me apply karna)
app.use(express.json())        -->  builder.Services.AddControllers()
                                     (already tune Program.cs me dekha hai)

STEP 1: PACKAGES INSTALL KARNA (jaise npm install karte hai)

Teri LibraryManagementAPI.csproj me abhi sirf ye 2 packages hai:
    - Microsoft.AspNetCore.OpenApi   (Swagger ke liye)
    - Swashbuckle.AspNetCore         (Swagger UI ke liye)

DB connectivity ke liye ye NuGet packages chahiye (npm install ka .NET version):

    dotnet add package Microsoft.EntityFrameworkCore.SqlServer
    dotnet add package Microsoft.EntityFrameworkCore.Design
    dotnet add package Microsoft.EntityFrameworkCore.Tools

    // Agar SQL Server ki jagah PostgreSQL use karna hai (mera personal suggestion,
    // free + cross-platform + Docker friendly), toh iski jagah ye use karo:
    // dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL

Ye 3 packages ka kaam:
    - SqlServer/Npgsql      -> actual DB driver (jaise "mongoose" package hi hai npm me)
    - EntityFrameworkCore.Design -> migrations banane ke commands ke liye
    - EntityFrameworkCore.Tools  -> "dotnet ef" CLI command chalane ke liye
      (jaise nodemon ek dev-tool hai, waise hi ye ek dev-tool hai, runtime me nahi lagta)

STEP 2: MODEL BANANA (jaise Mongoose Schema banate the)

Mongoose me tu likhta tha:

    const bookSchema = new mongoose.Schema({
        title: { type: String, required: true },
        author: String,
        isbn: String,
        publishedYear: Number
    });
    module.exports = mongoose.model("Book", bookSchema);

.NET me iska equivalent ek simple C# class hai (isse "POCO" bolte hai —
Plain Old CLR Object). Ye Models/Book.cs file me jayega:

    namespace LibraryManagementAPI.Models
    {
        public class Book
        {
            public int Id { get; set; }          // Mongo ka _id yahan "Id" (int) hai
                                                    // EF Core convention se "Id" naam
                                                    // dekhte hi ise Primary Key bana deta hai
                                                    // (auto-increment, jaise MySQL AUTO_INCREMENT)

            public string Title { get; set; } = string.Empty;   // required: true jaisa hi
            public string? Author { get; set; }                  // ? matlab optional field
            public string? Isbn { get; set; }
            public int PublishedYear { get; set; }
        }
    }

    // { get; set; } = C# ka "property" syntax — ise samajh:
    // JS me tu directly object.title = "abc" karta tha (no restriction).
    // C# me get/set "controlled access" dete hai — future me yahan validation
    // ya custom logic bhi daal sakta hai. Abhi ke liye bas ye maan le ki
    // ye ek "normal variable jaisa hi hai, thoda formal tarike se likha hua".

STEP 3: DbContext BANANA (ye tera "mongoose.connect()" + saare models ka manager hai)

Ye sabse IMPORTANT concept hai. DbContext ek class hai jo:
    1) DB se connection maintain karta hai
    2) Batata hai konse Models actual DB Tables banenge
    3) CRUD operations ke liye "gateway" ka kaam karta hai
       (jaise Mongoose model.find(), model.save() karte the, waise hi
        yahan context.Books.Add(), context.SaveChanges() karenge)

Data/LibraryDbContext.cs banao:

    using Microsoft.EntityFrameworkCore;
    using LibraryManagementAPI.Models;

    namespace LibraryManagementAPI.Data
    {
        // DbContext ko inherit karna zaroori hai — ye EF Core ki base class hai
        public class LibraryDbContext : DbContext
        {
            // Constructor — options (connection string, provider) yahan se aayenge
            // Ye "options" Program.cs me set karenge (STEP 5 me dekhenge)
            public LibraryDbContext(DbContextOptions<LibraryDbContext> options)
                : base(options) { }

            // DbSet<Book> = "Books" naam ka Table
            // Ye waisa hi hai jaise Mongoose me:
            //     const Book = mongoose.model("Book", bookSchema)
            // Bas yahan tu directly Table ko property ki tarah access karega:
            //     context.Books.Add(newBook)   // Book.create() jaisa
            //     context.Books.ToList()       // Book.find() jaisa
            //     context.Books.Find(id)       // Book.findById() jaisa
            public DbSet<Book> Books { get; set; }

            // Aage jaake agar "Member" table bhi banana ho (jo book borrow kare),
            // toh bas ek aur line add karni hai:
            // public DbSet<Member> Members { get; set; }
        }
    }

STEP 4: CONNECTION STRING (ye tera .env ka MONGO_URI hai)

appsettings.json me ek naya section add karo:

    {
      "ConnectionStrings": {
        "LibraryConnection": "Server=localhost;Database=LibraryDb;Trusted_Connection=True;TrustServerCertificate=True"
      },
      "Logging": { ... already hai ... },
      "AllowedHosts": "*"
    }

    // Mongo me tu likhta tha:
    //     MONGO_URI=mongodb://localhost:27017/libraryDb
    // Yahan same kaam ye connection string kar rahi hai — bas SQL Server
    // ka format thoda different hai (Server, Database, Auth details sab
    // ek hi string me).

Note: appsettings.Development.json me bhi ye daal sakta hai agar local aur
production ki DB alag rakhni ho (jaise .env vs .env.production).

STEP 5: Program.cs ME DbContext REGISTER KARNA (Dependency Injection)

Teri current Program.cs me ye lines hai:

    builder.Services.AddControllers();
    builder.Services.AddOpenApi();
    builder.Services.AddSwaggerGen();

Isi tarah, DbContext ko bhi "register" karna padta hai, taaki poori app me
kahin bhi (Controllers me) use ho sake — bina baar baar naya connection
banaye. Isse "Dependency Injection (DI)" bolte hai.

    using Microsoft.EntityFrameworkCore;
    using LibraryManagementAPI.Data;

    var builder = WebApplication.CreateBuilder(args);

    builder.Services.AddControllers();
    builder.Services.AddOpenApi();
    builder.Services.AddSwaggerGen();

    // ---- YE NAYI LINE ADD KARNI HAI ----
    builder.Services.AddDbContext<LibraryDbContext>(options =>
        options.UseSqlServer(
            builder.Configuration.GetConnectionString("LibraryConnection")
        )
    );
    // builder.Configuration.GetConnectionString(...) -> appsettings.json se
    // connection string uthata hai (jaise process.env.MONGO_URI karte the)

    var app = builder.Build();
    // ... baaki code same rahega ...

    // MENTAL MODEL: "AddDbContext" ka matlab hai —
    // "Jab bhi kisi Controller ko DB access chahiye, ek LibraryDbContext
    //  object automatically bana ke de dena" — isse "Constructor Injection"
    // bolte hai, aage Controller me dikhega kaise use hota hai.

STEP 6: MIGRATIONS (ye concept Mongoose me hota hi nahi hai — naya hai!)

MongoDB schema-less hota hai, isliye jo bhi field daalo, seedha DB me save
ho jaata hai — koi "table structure" pehle se banana nahi padta.

SQL Server jaisa relational DB me pehle Table ka structure (columns, types,
keys) actual DB me create karna padta hai. EF Core ye kaam "Migrations"
se karta hai — matlab ek script jo tere C# Model ko dekh kar SQL table
banane ka code generate karti hai.

    // Step A: Migration file generate karo (sirf ek "plan/instructions" file
    // banti hai, DB abhi tak touch nahi hui)
    dotnet ef migrations add InitialCreate

    // Step B: Actual DB me apply karo (ab table create hoga)
    dotnet ef database update

    // MENTAL MODEL:
    // "migrations add" = git commit jaisa hai (ek snapshot record hota hai
    //                     "is version me Book table me ye columns the")
    // "database update" = git push jaisa hai (ab wo changes real DB me jaate hai)

Jab bhi tu Model.cs me koi naya field add karega (e.g. "Genre" property),
tujhe phir se ye dono commands chalane padenge — taaki DB table bhi
sync ho jaaye.

STEP 7: CONTROLLER ME USE KARNA (yahan CRUD hoga — jaisa Express routes me)
--------------------------------------------------------------------------------
Controllers/BooksController.cs (tera routes/bookRoutes.js jaisa):

    using Microsoft.AspNetCore.Mvc;
    using Microsoft.EntityFrameworkCore;
    using LibraryManagementAPI.Data;
    using LibraryManagementAPI.Models;

    namespace LibraryManagementAPI.Controllers
    {
        [ApiController]
        [Route("api/[controller]")]   // -> /api/books  (auto route banta hai)
        public class BooksController : ControllerBase
        {
            private readonly LibraryDbContext _context;

            // "Constructor Injection" — ye wahi DbContext hai jo Program.cs
            // me AddDbContext se register kiya tha. .NET khud-ba-khud
            // isko yahan "inject" (pass) kar deta hai — tujhe khud
            // "new LibraryDbContext()" likhne ki zaroorat nahi.
            public BooksController(LibraryDbContext context)
            {
                _context = context;
            }

            // GET /api/books   -->  Book.find()
            [HttpGet]
            public async Task<ActionResult<List<Book>>> GetBooks()
            {
                return await _context.Books.ToListAsync();
            }

            // GET /api/books/5   -->  Book.findById(id)
            [HttpGet("{id}")]
            public async Task<ActionResult<Book>> GetBook(int id)
            {
                var book = await _context.Books.FindAsync(id);
                if (book == null) return NotFound();   // res.status(404)
                return book;
            }

            // POST /api/books   -->  Book.create(req.body)
            [HttpPost]
            public async Task<ActionResult<Book>> CreateBook(Book book)
            {
                _context.Books.Add(book);          // staging area me daala
                await _context.SaveChangesAsync(); // ab actual DB me commit hua
                // ^ Mongoose me .save() aksar ek hi step me ho jaata tha,
                //   yahan EF Core "track changes -> then commit" pattern follow
                //   karta hai (thoda git jaisa: add -> commit)
                return CreatedAtAction(nameof(GetBook), new { id = book.Id }, book);
            }

            // PUT /api/books/5   -->  Book.findByIdAndUpdate(id, req.body)
            [HttpPut("{id}")]
            public async Task<IActionResult> UpdateBook(int id, Book updatedBook)
            {
                if (id != updatedBook.Id) return BadRequest();
                _context.Entry(updatedBook).State = EntityState.Modified;
                await _context.SaveChangesAsync();
                return NoContent();
            }

            // DELETE /api/books/5   -->  Book.findByIdAndDelete(id)
            [HttpDelete("{id}")]
            public async Task<IActionResult> DeleteBook(int id)
            {
                var book = await _context.Books.FindAsync(id);
                if (book == null) return NotFound();
                _context.Books.Remove(book);
                await _context.SaveChangesAsync();
                return NoContent();
            }
        }
    }

QUICK RECAP — POORA FLOW EK NAZAR ME
--------------------------------------------------------------------------------
1. NuGet packages install (EF Core + DB provider)         -> npm install mongoose
2. Model class banao (Book.cs)                             -> mongoose.Schema
3. DbContext banao (LibraryDbContext.cs)                   -> mongoose.model()
4. Connection string appsettings.json me daalo             -> .env MONGO_URI
5. Program.cs me AddDbContext se register karo              -> mongoose.connect()
6. Migrations chalao (schema -> real DB table)              -> (Mongo me zaroorat nahi)
7. Controller me DbContext inject karke CRUD likho          -> Express route handlers

--------------------------------------------------------------------------------
EXTRA TIP: SQL Server vs PostgreSQL vs SQLite (kaunsa use karu?)
--------------------------------------------------------------------------------
- SQL Server  -> Windows-friendly, enterprise projects me common, Kanini jaisi
                 companies me use hone ka chance zyada (isliye seekhna useful)
- PostgreSQL  -> Free, open-source, cross-platform, tera MERN/Docker workflow
                 ke saath sabse zyada compatible feel hoga
- SQLite      -> Sabse simple, ek hi file me poori DB — sirf learning/local
                 practice ke liye best, production ke liye nahi

Agar sirf seekhne/practice ke liye hai toh SQLite se start kar (zero setup),
agar Kanini ke real environment jaisa practice karna hai toh SQL Server use kar.
